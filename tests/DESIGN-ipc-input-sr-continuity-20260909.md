# IPC 输入 SR 连续性修复与低延迟验收计划

## 状态与目标

2026-09-09：ZLM 输入时钟与 Stream Forge 配套实现已完成候选构建及针对性验证。1.203 的四路隔离预览从现有生产 `private-input` 拉流，经候选 ZLM 与 FFmpeg 输出到 `18554/live/1..4`；用户使用大华 NVR 对照后确认延迟有所降低，尚无量化的端到端毫秒结果。此接法包含原生产输入处理，不能替代候选直接连接 IPC 的完整验收；生产进程尚未替换。

按用户要求停止扩展实机测试。完整四机编码矩阵、真实断线恢复及长测仍有未完成项，不记为通过；下文保留测试计划与放行标准，区分已验证结果和后续部署验收。

提交前补修了同 SSRC 音频小幅 RTP 重置的恢复，以及不支持的播放控制仍返回成功的问题。ARM64 的 8 项时钟／codec／RTSP 回归、4 种模式共 16 次实际 HTTP 控制测试，以及 Stream Forge 的 84 项针对性测试通过。新重置链用例中 G711 在事件后约 2.08 秒完成既有 NTP 保护恢复，AAC 在新时间轴确认后恢复；全量样本保留，稳定后无相位残留。两项补修尚未部署到当前四路预览。

主要支持 G711A、G711U、AAC，播放出口以 RTSP／大华 NVR 为主。修复输入 SR 校准引起的音视频时间轴分离，同时保持持续低延迟。目标是**零新增固定等待、零新增媒体缓存，实际播放延迟不回退**；不把启动加速、时间戳正确或内部发送提速当作 NVR 显示改善。

本计划更新此前设计中“输入 SR 已全面处理”的范围判断。此前输出 ZLM 的共同 NTP 平移修复仍保留；它不能阻止源 ZLM 将相机输入 SR 的映射变化传入媒体 PTS。

## 修复范围

| 项目 | 本次拟改内容 | 兼容边界 |
| --- | --- | --- |
| ZLM | RTSP 拉流会话内统一处理输入 SR 观测与连续媒体时间轴；增加默认关闭的按代理选项及必要状态回读 | 不恢复全局 `NtpStamp` 平滑；不改变未启用代理、RTSP 推流、GB28181、WebRTC 的输入行为 |
| Stream Forge | 为受管 `private-input` 代理显式启用经过验证的模式；音频使用修正后的输入 PTS；补齐能力确认、命令及代理恢复核对 | 使用现有配置和生命周期路径，不增加通用时钟配置体系；旧 ZLM 不支持时不能静默套用新滤镜 |
| FFmpeg | 暂不新增源码补丁 | 保留 `rtsp_immediate=1` 和已验证的低延迟编码、发布参数；不恢复 `nobuffer` 或 `+rtcp_from_packet` 来掩盖问题 |
| G711／AAC 处理 | 保留已有按样本处理共用时间戳的边界，加入与新输入时钟的组合回归 | 不扩张 codec 白名单，不将未知 AAC 配置强行按 1024 样本处理；仅在回归证明需要时做局部衔接 |

预计运行时代码涉及两个项目；确切文件数在原型验证后确认，最终分别报告运行时代码与测试代码的 diff。若必须新增 FFmpeg 补丁或改变全局时钟语义，应先根据失败证据更新本方案。

### ZLM 的最小实现位置

优先在 `RtspPlayer` 会话内实现，而不是在每种音频解码器分别屏蔽 SR：同一会话已经能看到音视频轨及其 SR，能够统一判断。

当前 `RtpReceiver` 在排序前已调用 `NtpStamp` 生成时间戳，可能发生保护或截断。因此不能仅在解码前减去一个偏移；需要让启用模式取得原始 RTP 时间戳，并在既有排序之后形成媒体映射。按需要增加一个默认关闭的薄接入点，保留原来的 RTP／RTCP 收包统计、RR、排序和超时行为，不增加新的媒体队列。

预计触及 `RtspPlayer.cpp/.h`、必要的 `RtpReceiver` 接入、Client 选项，以及一个可独立回放的内部时钟实现／测试。复用现有 `addStreamProxy` 参数传递，不新增控制 API。若现有查询无法确认实际模式，可在代理状态中增加可选字段。

### 时间轴行为契约

先完成确定性原型和以下断言，再接入生产路径。

| 输入事件 | 必须得到的行为 |
| --- | --- |
| RTP 连续，两轨 SR 的 UTC 映射共同跳变 | 连续媒体轴不随墙钟阶跃移动；UTC 变化保留为观测，不变成播放等待 |
| 两轨 SR 先后到达，或只有一轨异常 | 不提前移动一轨，也不将单轨异常传播给另一轨；等待进一步时钟证据期间照常发送媒体 |
| 首份 SR 迟到、缺失或与接收机相差 8 小时 | 已输出时间轴不发生巨大跳变；不把绝对 UTC 偏差变成数小时渐进校正任务 |
| 正常持续频差 | 根据接收端单调时钟和 RTP 推进校准速率；验证音视频相对偏差和队列均有界，不积累无法消化的校正量 |
| 真实媒体缺失、停供、重连或时间戳重置 | 保留真实时间缺口或建立明确的新会话代次，不伪造未收到的媒体；恢复后不能留下永久偏移 |
| 旧 SR、SSRC 变化、RTP／序号回环及重排 | SR 只关联有效来源代次；合法回环不判为大跳，重排不使前进时钟状态回退 |

SR 中的 RTP 时间戳描述与其 NTP 对应的同一时刻，不保证等于邻近媒体包的 RTP；不能用“最后一包 RTP”无条件替换它。参见 [RFC 3550 §6.4.1](https://www.rfc-editor.org/rfc/rfc3550#section-6.4.1)。

首次 SR 到达前若没有可靠的跨轨参考，无法同时保证零等待、永不调整已输出时间轴、从首帧起精确声画同步。方案优先保证低延迟连续输出，明确记录初始参考是否建立，并用测试约束后续收敛；不承诺从未知信息恢复精确拍摄时间。

### 已实现的接收端时钟与限制

原型反例证明：把量化或反复小阶跃的 SR 用于渐进校正，仍会累积相位误差。因此当前实现只在轨道首次输出前使用兼容 SR 建立跨轨参考；后续 SR 保留观测，不控制已输出轨道的相位或速率。频率参考改为本会话的 `std::chrono::steady_clock`，不修改全局计时函数。

| 项目 | 当前行为 |
| --- | --- |
| 媒体推进 | 原 RTP 样本／帧时钟推进；在原排序器之后生成时间戳，不持有媒体包、不增加等待 |
| 同 SSRC 音频 RTP 回退 | 超过 250 ms 的回退由连续序号及三个推进的时间戳确认，再按到包参考建立新时间轴；重复／共用时间戳不计推进，返回旧正常时间轴撤销候选。视频不使用该确认分支，保留 B 帧语义；原有超过 3 秒的重置判定保留 |
| 重置恢复瞬态 | 确认期间媒体照常输出，不保证异常发生后的每包 PTS 都连续。G711 继续使用既有约 2 秒的持久 NTP 阶跃保护；链路回归检查样本守恒及恢复后无持续偏移，不通过增加媒体缓存掩盖瞬态 |
| 速率观测 | 每个完成的 5 秒区间保留一个最低到达延迟元数据点，每轨固定 64 点；至少 8 点且跨度 30 秒才拟合 |
| 噪声筛选 | 全窗口拟合失败时再拟合低残差样本；偏差限制 ±1000 ppm，三倍标准误差阈值 25 ppm 是筛选启发式，不是网络相关噪声下的严格置信保证 |
| 启动频差补偿 | 只在首次有效拟合且学习时间不超过 300 秒时建立一次补偿；总量上限 50 ms，按前进媒体时间每秒最多校正 1 ms；重复包、B 帧和 SR 不消耗或重建该补偿 |
| 运行中频率改变 | 后续速率连续更新，不反复追补历史相位；模拟运行中变为 ±100 ppm 会留下约 16–17 ms 常量偏差，不能宣称该场景误差小于 10 ms |
| 很晚才可学习 | 超过 300 秒才首次拟合时只修正后续速率；此前误差保留，不能宣称所有冷启动都精确收敛 |
| 网络可辨识性 | 单凭到包时间无法区分持续增长的网络队列与源频差；本模式假设局域网排队抖动有界，不能修复上游长期积压 |
| 初始参考不足 | 迟到 SR 不重写已输出相位；缺少首份有效 SR 时，历史 GOP 与真实跨轨拍摄相位可能不可恢复，不通过等待、丢帧或补音频掩盖 |
| 首份 SR 跨越校时 | 以第一份共同参考 SR 的 NTP／单调到达时间为基准；新轨首 SR 的两种时间差相差达到 250 ms 时回退到到包参考。该检查与 10 秒报文年龄／历史 GOP 范围独立，不能把报文新鲜等同于时钟可信 |
| 首份参考的精度 | 阈值内的异常 SR、差异化网络排队和真实跨轨相位无法严格区分；每轨仅记录一次 `accepted early SR` 或 `arrival fallback` 调试日志，前者不表示精确同步认证 |

本地独立确定性测试已覆盖 4 个随机种子 × ±100／0 ppm 的两小时批到包抖动：稳态误差不超过 6 ms，无持续累积；SR 的 ±16／32／100 ms 重复阶跃及大阶跃不会改变已运行输出。该结果不是两小时实机灰度，也不是 NVR 显示延迟测量。

### Stream Forge 的配套调整

当前 `aresample=16000,asetpts=STARTPTS+N/SR/TB` 每次都以累计样本数重写音频时间戳，会丢掉后续输入 PTS 中的时间关系。首个候选是保留 `aresample=16000` 并使用修正后的 PTS，**只能与通过验证的输入模式配套启用**。同时验证现有视频 `setpts` 对负向变化、真实断流和重连的影响；仅在发现必要性后局部调整。

不默认添加 `async=1000`。原生 `aresample` 的时间戳补偿可以拉伸、压缩、插入或删除音频，相关能力见 [FFmpeg aresample 文档](https://ffmpeg.org/ffmpeg-filters.html#aresample)。若真实频差确实需要补偿，另设最小实验，明确样本计数与音质验收，不能混同于纯 SR 事件处理。

| 配置／接口项 | 计划语义 |
| --- | --- |
| 新输入模式 | ZLM `rtsp_input_clock=0` 默认关闭；仅值 1 请求启用，不写死 `private-input` 业务名称 |
| 生效回读 | 现有代理 JSON 增加整数 `inputClockRequested`／`inputClockMode`；请求开启不等于生效，离线／握手未成功时有效模式为 0 |
| Stream Forge 开关 | `stream-forge.zlm.lifecycle.input-clock-enabled=false` 默认关闭；另用 `input-clock-channels` 显式选择通道，空集合不启用任何通道。仅非 DEV 的受管 RTSP／ONVIF 输入适用，必须确认代理在线且有效模式为 1 才移除音频 `asetpts` |
| 支持范围 | 首轮限定显式启用的直播 RTSP、重打包路径；回放／seek、`directProxy=1` 不进入此模式，不能静默改写用户直转配置 |
| 播放控制 API | 有效模式为 1 时，暂停、跳转和非 1 倍速返回现有 `API::InvalidArgs`（`code=-300`），不发送上游控制；1 倍速与有效模式为 0 的原行为保留。仅请求开启但实际回退为 0 的代理仍可正常控制 |
| 本机参数 | 使用 1.203 实际有效值：`modify_stamp=0`、`directProxy=0`、现有低延迟及零定时发送参数；不得复制上游默认配置 |
| 未来修改默认值 | 本机显式值优先；另测 `modify_stamp=1/2` 的既有语义，不锁死为 0 |
| 新旧版本混用 | 先确认 ZLM 支持且代理实际启用，再切换滤镜；不支持时保持旧行为并明确状态，不半套切换 |
| 更新与恢复 | 将所选模式纳入既有代理恢复核对；新会话读取配置，按既有生命周期核对新会话，不在运行中悄悄切换时钟；当前配置修改需要服务重启，其影响范围见灰度章节 |

## 低延迟的独立验收

### 比较对象与测量方法

需要两种对照：候选对当前健康启动的版本，用于隔离本次变更；候选对完整上一版本，用于回应实际使用中的回退。不能用已经积累异常偏移的进程作为唯一基线。

完整上一版和候选版分别使用自己的 source ZLM、FFmpeg、输出 ZLM，不能共用候选 source ZLM。优先在它们之前分发字节等价的原始 RTP／RTCP；否则使用同相机同 profile 的独立会话，并按内容配对。若并发分支造成相机会话不足或设备过载，改用相同四路负载的反复交替试验，记录限制。

目前保留了旧 FFmpeg 原始产物（SHA256 前缀 `803b688f`）；旧 ZLM 原始产物（`14d79941`）尚未找回。优先查包缓存／归档，必要时根据旧源码和完整补丁重建。重建结果必须标为“旧源码重建基线”，不能声称逐字节复现了旧生产版本。此限制不阻止正确性验证，但会限制“优于真实上一版”的结论。

| 测量 | 方法 |
| --- | --- |
| 服务端延迟 | 四机当前 profile 各做同源成对 10 min ×3 轮，交换启动次序；分别量输入转发、压缩处理、发布转发，按内容关联；不能跨转码直接假定压缩包哈希相同 |
| 统计 | 每 5 s 配对窗口，报告 P50／P95／P99、尾部事件和 95% 不确定性；按时间窗口估计相关性，不把每帧当独立样本 |
| 真实 NVR 显示 | 大华 NVR 同屏对比直接 IPC、旧链路、候选链路；固定主／子流、布局、刷新率和读者数，交换窗口位置，至少 3 轮共同可见事件计时 |
| 显示精度 | 使用高速同屏录像或可重复的外部计时事件，建议 ≥240 fps；记录显示扫描／刷新及视频帧率造成的不确定性。现有工具不能分辨 10 ms 时补充测量，不写“无回退” |
| 内容声画同步 | 使用共同闪光／声音事件核对 NVR 实际播放；音频开启、单／多画面分别验证；时间戳前沿差只作诊断 |
| 资源与证据 | 性能测试关闭高频调试日志；同时记录 CPU、RSS、帧率、码率、温度及丢帧；采集缺首包或出现非预期抓包丢失时，该测量重做 |

### 放行标准

1. **目标零新增固定等待、零新增媒体缓存。** 时钟判断可以保留少量控制状态，不能等待第二轨 SR 后才发送媒体。
2. 候选减健康基线的 P50、P95 目标均不大于 0。P50 增加超过 2 ms 或 P95 超过 5 ms 进入调查；**可重复的 10 ms 级回退不放行**。统计与测量精度不足以排除这一回退时继续补测。
3. 服务端成对差值的单侧 95% 置信上界目标不超过 +5 ms；NVR 以实际可达到的测量精度单独报告。不能用服务端数字替代 NVR 验收，也不能将屏幕刷新噪声当作确定收益。
4. P99 与停顿逐事件检查；尾部样本不足时不据此宣称通过。不得以牺牲音频、额外丢帧、降码率或改 GOP 获得低延迟数字。
5. 已知纯 SR 注入事件不得制造内容声画错位或累积媒体前沿分离；现场稳定窗口的前沿变化作为辅助指标，不能硬性要求前沿等于 0。真实断流的恢复与固定编码延迟分别评价。
6. 25–40 ms 是希望保住或获得的收益，实测确认后才报告；本次不提前承诺具体收益。

## 灰度、回滚与交付

1. 先部署支持新选项但默认关闭的 ZLM，确认旧路径不变及新能力可回读，再部署配套 Stream Forge。实际是否需要重启整个 ZLM 进程由部署方式决定，不能承诺二进制替换不影响其托管流。
2. 仅为大华通道启用成套模式与滤镜，重建对应源／FFmpeg 会话，观察至少 2 小时；通过后逐路扩大，完成四路 24 小时灰度。生产期间不注入相机时钟故障，注入测试只在隔离路径进行。
   当前 Stream Forge 开关／通道集合在构造时读取，需要重启服务。正常退出会清理全部 `private-input`，启动时重建所有已启用通道的 FFmpeg；通道集合只限定新时钟语义，不限制重启影响。部署及扩大集合时需核对全路预览恢复，不承诺只中断选中通道。
3. 模式、滤镜和会话重建作为一套回滚步骤；保留可恢复的完整产物、配置和命令。检查实际读者恢复及其他通道状态。回退到旧行为只代表恢复服务，不等于缺陷已修复。
4. 最终交付：两个项目的最小运行时 diff、与上游差异说明、模式关闭兼容回归、必要脱敏 fixture、四机结果表、服务端与 NVR 延迟报告、部署／回滚步骤。未通过项和重建旧基线的限制单列。

交付状态按实际阶段记录；构建、隔离测试、四机矩阵、长测和 NVR 显示验收分别判定，不以原型测试代替实机结果。
