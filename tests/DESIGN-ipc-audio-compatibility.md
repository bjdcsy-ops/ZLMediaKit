> [本机配置冷启动与小修报告](REPORT-ipc-coldstart-minimal-fixes-20260908.md)。

2026-09-08，按用户最新要求收敛：主要支持 G711 和 AAC，以现有 RTSP/NVR 为主，
优先靠近 ZLMediaKit 官方实现，控制公共模块的行为变化与维护成本。

本文替代此前的多 codec 接入、source/steady 双模式和 AAC 来源代次设计。
最小 codec 候选已在 `codex/g711-aac-minimal` 工作树实施并完成 ARM64 构建。
1.203 已执行独立端口测试；生产程序未替换。原 SR 回放仍失败，候选不满足生产替换门槛。
具体结果见 [回归记录](README-audio-timestamps.md#最小候选实施与验证2026-09-08)。

## 支持边界

| 输入 | 本次范围 |
| --- | --- |
| PCMA / PCMU 8 kHz 单声道 | 保留标准 PT8/PT0 与既有行为 |
| 显式 PCMA / PCMU 16/32 kHz、不同声道 | 保留上游 SDP 真实规格；正确使用动态 PT，不强制改成 8 kHz 单声道 |
| G711 正常逐包、相位抖动、成批共戳 | 局部样本规范化，payload 守恒，正常包即时解包 |
| AAC | 保留已有 MPEG4-GENERIC/AAC-hbr 解包路径；重点验收 AAC-LC、1024 samples/AU 的当前 IPC |
| AAC 聚合/分片 | 当前 AU 时间、AU-index 偏移、首片归属、缺片保护与完整 AU 即时输出 |
| HE-AAC、960 samples、LATM 等 | 不扩大支持承诺，不新增自动转换路由；保留原有行为并明确测试未覆盖的布局 |

本轮不新增 G722/G726/Opus/L16 专用处理、不改业务输入路由、不加入按通道音频 profile。
这些格式原有能力不因本次被主动删除。

## 最小保留集

### G711

保留已提交的局部修复和本次成批共戳补充：

- G711Track 尊重采样率与声道，参数传递至 decoder/encoder，WAVE 元数据与实际规格一致。
- decoder 按 payload 每声道样本数推进；完整包当次交付，不采用 CommonRtp 等下一时间戳的路径。
- encoder 按样本位置分包，保持 MTU、声道对齐、尾包 flush 和静态 PT 约束。
- 连续序号、同 SSRC、共享时间戳才提供批次证据；相对累计样本轴最多 80 ms 容差，不逐批重锚。
- 保留已验证的重复/历史包保护、同 SSRC 重启候选与明确间断；不新增排序器公共重启事件。

80 ms 是输入兼容容差，不是增加 80 ms 缓冲；限内真实小暂停仍可能被平滑，这是已有取舍。
20 ms 输出分包有现有拼包余量，不把“即时解包”表述为整条路径零缓存。

G711 的四个核心文件相对官方目前为 +387/−36，其中包含已提交修复。
这部分确实多于原版：原版硬编码 8 kHz/单声道，解包复用 CommonRtp，不能保留原样又解决
已经复现的 16/32 kHz 与批次时钟问题。

本地 G711 NTP deadband/slew/持续大偏差处理可另减少约 40 余行及 5 个字段，但会撤回
已验证的抗抖行为；本批不把它当无行为变化的清理。历史包保护与一包重启候选同样有反例支撑，
不为了减少行数转而增加跨层框架。

### AAC

保留已提交的 AAC decoder 正确性修复；撤出本轮的精度 metadata：

| 保留 | 撤出本批 |
| --- | --- |
| 使用当前完整 AU 的时间戳 | AACRtpFrame 及 raw RTP 绝对时间戳透传 |
| AAC-hbr 聚合 AU-index/帧长处理 | AAC.cpp 中额外 metadata 拷贝与传递 |
| 分片沿用首片时间，缺片/重复保护 | 为保留精度而增加的来源代次、输出原点、live 开关和资格体系 |
| 完整 AU 即时输出、原 ADTS 逻辑 | 对 RtspSession 的 NPT/Range 契约扩展 |

AAC encoder 和 AACTrack 回到官方的普通 Frame/DTS 结构；AACRtp.cpp/.h 仍保留既有
解包修复，两文件相对官方 +98/−34。撤出本轮 exact 涉及三文件 +64/−13 的差异。

接受原有毫秒 Frame 精度：1024 samples/AU 在 44.1 kHz 下通常呈 23/24 ms，48 kHz
为 21/22 ms，16 kHz 为 64 ms。量化不是新增排队，不等于逐帧不断积累的时间缺口；
不再承诺毫秒 Frame 路径保留逐 AU 精确样本时间。

撤出 raw 绝对时间戳传递后，不需要为它新增跨输入时钟域和点播映射框架。必须以之前的
retained-muxer 重连、VOD 两个反例验证，不能仅根据删掉字段宣称兼容性已经验收。

## FFmpeg 与尚未关闭的 SR 问题

FFmpeg 在隔离工作树撤回本轮固定 origin 的语义替换，恢复此前 rtcp_from_packet。
另恢复 9 月 4 日独立验证过、当时未提交/未部署的 AAC 当前 AU 即时发送补丁：
`rtpenc_aac.c` 仅一处条件变化（+3/−1，包含两行说明），三个文件用于真实 mux/FATE 回归。
不新增 SR 模式，不扩大编码范围，也不在本批改业务音频滤镜。

但这个方向不能单独部署：原 live/3 已证明旧 FFmpeg 的 SR 相位变化与 ZLM 官方硬重锚
共同导致视频/AAC 时间回退。恢复官方接收逻辑及 AAC DTS 后，原始反例仍然成立。
G711/AAC 包处理正确不等于 SR 重锚问题已修复。

因此分清两项交付：

1. **最小 codec 补丁基线：**G711 参数/分包/批次兼容，AAC 完整 AU/分片正确性，公共模块尽量恢复官方。
2. **SR 问题的独立最小修复：**保留原始失败回放，比较纯官方、最小 codec 候选、现部署版本，
   再决定确有必要的额外改动。本轮不预先加入 source/steady 模式，也没有证据声称一两行即可
   兼顾全部时钟抖动、频差、停供和重启。

不能用现部署 fixed-origin 暂时遮住问题来宣布第一项替代了完整现场修复；也不能通过删除
SR 断言、忽略失败窗口或只看“告警没了”来验收。
